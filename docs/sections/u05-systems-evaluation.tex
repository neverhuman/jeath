\section{Live Checkpoint Evaluation, Fence Ablation, and API Census}\label{sec:systems}

\subsection{Usefulness, Zero False Blocks, and the Live Fence Ablation}

A practical capability gate must preserve benign task usefulness rather than achieving safety by blocking everything. We evaluate five equal-permission controllers on a SHA-256-frozen holdout of \(N = \VFourHoldoutCasesPerCheckpoint\) independent tool-use cases per checkpoint using local Qwen3-4B and Qwen3-8B models, alongside \(24\) live AgentDojo v1.2.2 episodes (\(12\) distinct base tasks \(\times 2\) prompt-injection and authority-withdrawal scenarios) per checkpoint (Table~\ref{tab:v2eval}).

Three empirical findings stand out in Table~\ref{tab:v2eval}:
\begin{enumerate}
  \item \textbf{Mediation improves safe usefulness with zero false blocks.} Complete mediation records \(0/64\) benign false blocks across both frozen holdouts and achieves the highest safe-and-useful task completion: \(\VFourFourBCompleteSafeUsefulCount/\VFourHoldoutCasesPerCheckpoint\) (\(\VFourFourBCompleteSafeUsefulPct\%\)) on Qwen3-4B and \(\VFourEightBCompleteSafeUsefulCount/\VFourHoldoutCasesPerCheckpoint\) (\(\VFourEightBCompleteSafeUsefulPct\%\)) on Qwen3-8B, compared with \(\VFourFourBNoneSafeUsefulCount/\VFourHoldoutCasesPerCheckpoint\) (\(\VFourFourBNoneSafeUsefulPct\%\)) and \(\VFourEightBNoneSafeUsefulCount/\VFourHoldoutCasesPerCheckpoint\) (\(\VFourEightBNoneSafeUsefulPct\%\)) unmediated. Deterministic refusal feedback lets the model pivot cleanly to in-policy actions instead of corrupting episode state.
  \item \textbf{Same-model reviewers leak on both checkpoints.} Prompting the same checkpoint to audit proposed tool calls permits \(\VFourFourBLearnedUnauthCount/\VFourHoldoutCasesPerCheckpoint\) (\(\VFourFourBLearnedUnauthPct\%\)) unauthorized commits on Qwen3-4B and \(\VFourEightBLearnedUnauthCount/\VFourHoldoutCasesPerCheckpoint\) (\(\VFourEightBLearnedUnauthPct\%\)) on Qwen3-8B.
  \item \textbf{Broker revocation without sink fencing fails in live runs.} Across the \(\VEightTotalWithdrawCases\) holdout episodes that withdraw authority mid-flight (\(6\) per checkpoint), revoking admission at the broker without fencing the sink (\emph{Durable, no sink fence}) still permits \(\VEightTotalNoFencePostWithdraw\) queued post-withdrawal commits (\(\VEightFourBNoFencePostWithdraw\) on 4B and \(\VEightEightBNoFencePostWithdraw\) on 8B). Adding the cooperative sink epoch fence reduces post-withdrawal commits to \(0\) across all \(\VEightTotalWithdrawCases\) revocation cases at \(\VFourFourBFenceAckMs\)--\(\VFourEightBFenceAckMs\)\,ms mean fence acknowledgment latency.
\end{enumerate}

On live AgentDojo v1.2.2 episodes, upstream Progent static policies~\cite{progent,progent-code} block all \(24\) direct prompt-injection attacks (\(0\) native injection breaches), confirming the strength of per-call argument schemas, but permit \(\VFourDojoProgentBudgetBreachCount\) cumulative shared-budget breaches across multi-step spend loops where stateful reservation is required.

\subsection{Live Best-of-\(K\) Candidate Search Against Learned Reviewers}

To measure Proposition~\ref{prop:optinvariance} with real language-model proposals rather than synthetic miss formulas, we draw \(K \in \{1,2,4,8,16\}\) stochastic candidate tool proposals (\(\VEightBokTotalCandidates\) live candidate generations across \(\VEightBokCasesPerModel\) adversarial tasks per checkpoint) from Qwen3-4B and Qwen3-8B and evaluate each candidate against both the same-checkpoint reviewer and the Verus-verified sink gate (Figure~\ref{fig:v5hero}b). On Qwen3-4B, cumulative reviewer bypass climbs from \(\VEightBokFourBSinglePct\%\) at \(K = 1\) to \(\VEightBokFourBSixteenPct\%\) at \(K = 16\); on Qwen3-8B, bypass climbs from \(\VEightBokEightBSinglePct\%\) to \(\VEightBokEightBSixteenPct\%\). Empirical bypass grows more slowly than the naive i.i.d.\ curve \(1 - (1 - \hat{p}_1)^K\) because candidates drawn for the same prompt correlate (\(\hat{\rho}_{\mathrm{cand}} = \VEightBokFourBRho\) on 4B; \(\VEightBokEightBRho\) on 8B), yet still trends monotonically upward with \(K\), whereas the verified sink gate admits \(0\) unauthorized commits at every \(K\).

\subsection{Production API Fence-Ability Census}

Because our zero-leak revocation guarantee covers only cooperative sinks (\textbf{C1}, \textbf{C3}), practical deployment depends on how many real-world tool APIs support idempotency or conditional-write preconditions. Five interfaces (Stripe, Kubernetes, S3, PostgreSQL, Google Cloud Storage) natively enforce idempotency keys, resource-version compare-and-swap, or transactional locks; four more (GitHub Git refs, Terraform state, Slack chat updates, Jira issues) support proxy-enforced compare-and-swap via expected commit hashes or version tags (\(\VEightCensusCooperativeOrShim/\VEightCensusTotalApis\) cooperative or proxy-fenced total). Three outbound communication APIs (SendGrid scheduled mail, Gmail drafts, Twilio queued messages) require a local pre-dispatch hold window to support cancellation, while raw SMTP relay and unauthenticated webhooks lack revocation primitives and must be treated explicitly as uncooperative exposure \(u > 0\).

\para{Statistical accounting.} In Table~\ref{tab:v2eval}, \(0\) unauthorized commits under complete mediation is an integration soundness property---the gate and grader enforce the same capability specification---rather than a stochastic risk estimate, so hypothesis-test \(p\)-values against zero mediated breaches are uninformative.
