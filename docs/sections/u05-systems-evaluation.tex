\subsection{Invariant Omissions and Snapshot Non-Composition}
Exhaustive finite-state exploration of the preserved V1 22-action model (\texttt{12b5579}; Appendix~\ref{app:protocol}, Table~\ref{tab:results}) visits \CheckedStates{} reachable states and \CheckedEdges{} transition checks with zero declared violations and $20/20$ positive tasks passing, whereas nine single-clause mutations each produce a shortest counterexample. Removing only the aggregate-budget clause from the specification while keeping per-action limits expands the accepted graph to \OmittedStates{} states (\OmittedEdges{} checks) with zero declared violations, yet spends $8$ units against an intended allowance of $2$---showing that neither positive tests nor exhaustive checking detects an omitted protected interest.

Concurrent snapshot checking fails even when aggregate limits remain in the specification. Over all \VThreeCompHundredTriples{} integer triples $(c, q_1, q_2) \in \{0,\dots,100\}^3$ at budget $B = 100$, \VThreeCompHundredAdmissible{} pairs satisfy per-request snapshot admissibility ($c + q_1 \le B$ and $c + q_2 \le B$), yet \VThreeCompHundredOverspend{} (\VThreeCompHundredOverspendPct\%, matching the closed form $\frac{B}{2B+3}$ in Appendix~\ref{app:proofs}) jointly overspend ($c + q_1 + q_2 > B$), compared to \VThreeCompHundredSerializedOverspend{} overspends under serialized reservation. Across V2's abstract separate-store mutation model (\path{ablate_v2.py}), omitting each of ten mechanisms (cumulative budget, payload binding, issuer conjunction, epoch freshness, expiry, revision matching, deduplication, durable accounting, uncertainty quarantine, and sink fencing) individually and in all $45$ pairs yields concrete violation witnesses in all \VTwoAblationWitnesses/\VTwoAblationSets{} omission sets across \VTwoTraces{} searched subsequence traces, while the complete model admits positive work with zero harms (witnesses are minimal only within the declared template language, and pairwise witnesses may reuse single-omission prefixes).

\subsection{Fault Injection, Linearizability, and Negative Controls}
In separate-process SQLite testing (\path{run_v2.py}), all \VTwoFaults/\VTwoFaults{} sequential RPC fault and crash histories match an independent Python \texttt{Reference} specification on both intermediate responses and final \path{sink.sqlite} effects. These cover \VTwoPositiveFaults{} semantic positive controls (\texttt{transfer}, \texttt{release}, \texttt{edit}), pre- and post-commit process death (\texttt{exit 86}/\texttt{87}) with restart recovery, \texttt{lost\_reply} quarantine, stale-revision cancellation, multi-issuer quorum splits, attenuated sub-delegation, \VTwoServiceCapBytes-byte oversize-frame recovery, and \path{delegated_transfer_extra_steward_fenced} (verifying that a delegated transfer carrying a strengthened steward requirement is cancelled by a steward sink fence).

Concurrency verification separates three distinct scopes rather than conflating in-memory schedules with database linearizability:
\begin{enumerate}
\item \textbf{Bounded in-memory schedule exploration} (\path{protocol_v2_interleavings.rs}) checks Rust \texttt{Broker}/\texttt{Sink} interleavings across withdrawal, renewal, fence delivery, \texttt{lost\_reply} settlement, delegated steward fencing, and four proposer strategies (\texttt{guardian}, \texttt{warrior\_\allowbreak opportunistic}, \texttt{replay\_storm}, \texttt{adaptive\_\allowbreak boundary\_\allowbreak seeker}), without modeling SQLite I/O.
\item \textbf{Recorded-RPC real-time interval linearization} (\path{concurrent_v3.py}) searches actual separate-process SQLite histories against the independent Python \texttt{Reference} respecting invocation/response partial order ($\texttt{responded\_ns} < \texttt{invoked\_ns}$), checking decision and public \texttt{status} responses plus exact canonical final \texttt{effects} (including strengthened \texttt{required} vectors). Non-atomic administrative \texttt{inspect}/\texttt{audit} snapshots are excluded, and traces crossing expiry windows or exceeding the \VTwoLinearizedMaxCalls-call ($10^5$-node) bound are marked \texttt{inconclusive}, never passed; all \VTwoLinearizedRuns/\VTwoLinearizedRuns{} publication runs across $1, 2, \VTwoLinearizedMaxActors$ concurrent actors pass.
\item \textbf{High-contention SQLite races} (Figure~\ref{fig:v2runtime}a) test \VTwoRacePopulations{} populations ($1, 2, 4, 8, 16, \VTwoRaceMaxActors$ writers; \VTwoRaceRuns{} runs on \texttt{xbabe2}), where $8, 16, \VTwoRaceMaxActors$-actor runs exceed the \VTwoLinearizedMaxCalls-call bound and pass independent final-state conservation ($8$-unit cap, $0$ overspends) and \texttt{audit} integrity with p95 lock-wait latencies.
\end{enumerate}

Three negative controls bound system claims: (i) holding an active sink transaction for \VTwoRevokeInjectedDelayMs\,ms delays synchronous \texttt{fence} acknowledgment to \VTwoRevokeFenceAckMs\,ms while the prior $8$-unit transfer commits legitimately before acknowledgment (\VTwoRevokeUnavailableUnits{} units unavailable afterward; zero post-acknowledgment effects on retry); (ii) retrying an ambiguous delivery against an uncooperative non-idempotent sink (\path{nonidempotent_v2.py}) produces \VTwoUnsupportedSinkEffects{} duplicate effects, confirming that local SQLite accounting never confers external API idempotence \cite{limbo}; and (iii) an approved wrong edit (\texttt{return 0} vs.\ \texttt{42}) commits under \path{policy-core} and fails the semantic task oracle, confirming that permission verification does not establish semantic adequacy. On Linux, \VTwoProbes/\VTwoProbes{} confinement probes fail closed while unrestricted canaries succeed (\VTwoBaseProbes{} binary probes plus \path{existing_sysv_queue}, proving confined \texttt{msgsnd}/\texttt{msgrcv} on a pre-existing \texttt{IPC\_PRIVATE} queue fail with \texttt{EPERM}, alongside the \path{launch_v2.py} \texttt{stderr=DEVNULL} descriptor-leak regression and \VTwoLauncherCapBytes-byte oversize-line recovery).
