\section{Protocol Transitions, Finite-State Models, and Boundary Schemas}
\label{app:protocol}

This appendix records the durable storage schemas, remote-procedure-call (RPC) transition rules, Linux kernel confinement filters, mechanized Verus verification inventory, and 22-action finite-state and single-database baselines referenced in Sections~\ref{sec:core} and~\ref{sec:eval}.

\subsection{Separate-Process Broker and Sink Durable Schemas}
Both the Authority Broker and Cooperative Idempotent Sink require SQLite $\ge 3.51.3$ (excluding historical write-ahead-log reset bugs \cite{sqlite-wal}), configure write-ahead logging (\texttt{WAL}), full synchronous durability (\texttt{FULL}), and a $10$\,s lock-wait timeout, and execute every mutating RPC inside an explicit serialized immediate-write transaction (\texttt{BEGIN IMMEDIATE}) \cite{sqlite-transaction}. Physically, each service store initializes two relational tables:
\begin{itemize}
\item \texttt{state(singleton INTEGER PRIMARY KEY CHECK(singleton=1), body TEXT NOT NULL)}: stores the canonical serialized service state record for the broker or sink shard.
\item \texttt{effects(sequence INTEGER PRIMARY KEY, id TEXT UNIQUE NOT NULL, payload TEXT NOT NULL, charge INTEGER NOT NULL)}: used in each sink shard as an append-only committed effect log enforcing database-level uniqueness on operation identifier \texttt{id} and recording the canonical dispatched permit alongside integer \texttt{charge}.
\end{itemize}

\para{Normalized dispatched-permit binding.}
For $n$ configured issuers ($1 \le n \le 64$, default $n = 2$), base operation requirements $\mathrm{req}_0(e, n)$ require issuer $0$ (operator) for value transfers, issuers $\{0,1\}$ (operator and steward) for resource edits, and all $n$ issuers for external releases. When a proposal is admitted via a sub-delegation leaf whose required-issuer vector strengthens $\mathrm{req}_0(e, n)$ (for example, adding steward requirement $j=1$ to a transfer), submission embeds the leaf's strengthened requirement vector into the dispatched wire permit. At the sink, normalization rejects any vector that weakens $\mathrm{req}_0(e,n)$ and supplies the effective required-issuer set to acceptance, completion, fencing, and integrity auditing. Meanwhile, broker submission compares the base canonical permit ($\text{actor} + \text{proposal}$) on proposer retries so repeating a request returns its stored status and dispatched permit idempotently without permitting a stripped sink replay.

\subsection{Broker and Sink RPC Transition Specification}
Every service request frame enforces a \VTwoServiceCapBytes-byte cap and a POSIX poll per-frame deadline (default $500$\,ms; oversize frames drain to newline and return a size-limit denial, while stalled partial frames return a timeout denial without terminating the service). Deterministic fault-injection hooks (configurable pre-commit lock hold up to $1000$\,ms, deterministic crash prior to transaction commit, and deterministic crash immediately after transaction commit) exercise write-ahead-log lock contention and crash recovery.

\para{Authority Broker transitions.}
\begin{itemize}
\item \textbf{Initialize$(B, n)$:} Fails if initialized; otherwise sets cap $B$, charged spend $C = 0$, $e_{\mathrm{iss}} = 0^n$, $\mathrm{live} = \mathrm{true}^n$, and empty approvals, reservations, and delegations.
\item \textbf{Approve$(\text{permit}, j)$:} Requires $\mathrm{live}[j]$, matching issuer epochs, no identifier collision in delegations, and exact canonical byte equality if an approval for that proposal identifier already exists; records grant bit $j$.
\item \textbf{Delegate$(\text{id}, \text{parent}, B_k, T_k, \text{scope}, \text{req})$:} Verifies ancestor acyclicity, live current ancestor grants, absence of non-cancelled direct spend on ancestor records, and stepwise capability attenuation before appending the delegation.
\item \textbf{Submit$(\text{proposal}, \text{session-actor})$:} If the proposal identifier is already recorded, returns stored $(\text{status}, \text{permit})$ iff the base permit matches $\text{session-actor} + \text{proposal}$, else denies as a payload mismatch. Otherwise verifies scope, checks direct approval or full ancestor delegation liveness and multi-issuer admission, reserves $C' = C + q \le B$ (and $C'_k = C_k + q \le B_k$ along any delegation lineage), persists a \emph{Pending} reservation, and returns \emph{Pending}.
\item \textbf{Withdraw$(j)$:} Increments $e_{\mathrm{iss}}[j] \leftarrow e_{\mathrm{iss}}[j] + 1$, sets $\mathrm{live}[j] \leftarrow \mathrm{false}$, clears issuer-$j$ grants across all approvals and delegations, and reports outstanding in-flight exposure $\sum \{q_r : r\text{ Pending} \land \mathrm{req}_r[j]\}$.
\item \textbf{Renew$(j)$:} Sets $\mathrm{live}[j] \leftarrow \mathrm{true}$ without restoring cleared grant bits, altering $e_{\mathrm{iss}}$, or reducing $C$.
\item \textbf{Settle$(\text{id}, \text{terminal-status})$:} Control-plane endpoint (never exposed to proposers). Requires an existing \emph{Pending} reservation and authoritative sink status $\in \{\text{Committed}, \text{Cancelled}\}$; refunds $q$ iff \emph{Cancelled} and seals terminal status.
\item \textbf{Status / Inspect / Audit:} Read-only queries; audit runs SQLite database integrity verification and checks identifier uniqueness, delegation bounds, and $\sum_{\text{Pending}} q + \sum_{\text{Committed}} q = C \le B$.
\end{itemize}

\para{Cooperative Sink transitions and concurrent linearization.}
\begin{itemize}
\item \textbf{Accept$(\text{permit})$:} Normalizes the dispatched permit. If its identifier is already recorded, returns stored status iff the full dispatched permit matches byte-for-byte, else denies as a payload mismatch. If new and any effective required issuer fails $e_{\mathrm{iss}}[j] \ge F[j]$, persists a terminal \emph{Cancelled} tombstone; otherwise persists \emph{Pending}.
\item \textbf{Complete$(\text{id})$:} Requires a recorded permit. If \emph{Pending}, re-evaluates $e_{\mathrm{iss}}[j] \ge F[j]$, active lease horizon $t < L_m$, relational mutexes, and (for edits) expected resource revision. Failure transitions status to \emph{Cancelled}; success updates the target resource if applicable, transitions status to \emph{Committed}, and appends the unique row to \texttt{effects} inside the same immediate-write transaction. Terminal records return stored status idempotently.
\item \textbf{Fence$(j, \text{floor})$:} Updates $F[j] \leftarrow \max(F[j], \text{floor})$ and transitions every \emph{Pending} permit failing the updated floor to \emph{Cancelled} before committing and returning a signed acknowledgment.
\item \textbf{Status / Inspect / Audit:} Status returns \emph{unknown} when absent (never treated as cancellation); audit verifies database integrity, epoch-floor compliance across all remaining \emph{Pending} permits, and exact payload and charge bijection between \emph{Committed} permits and \texttt{effects}.
\end{itemize}
For concurrent separate-process runs, our interval-linearizability verifier checks real-time order against the independent reference specification using diamond partial-order reduction (exploiting commutativity of budget-rejected submissions) and canonicalized state memoization across all $1..\VTwoLinearizedMaxActors$-writer populations ($\VTwoLinearizedRuns/\VTwoRaceRuns$ runs, $\le \VTwoLinearizedMaxCalls$ RPCs): an invocation $e_j$ must precede $e_i$ whenever $t_{\mathrm{resp}}(e_j) < t_{\mathrm{inv}}(e_i)$; pre-commit crashes commit $\mathrm{false}$, post-commit crashes commit $\mathrm{true}$, and unannotated dropped replies branch over $\{\mathrm{false}, \mathrm{true}\}$. Every linearized prefix must match recorded decisions and public status responses, maintain $0 \le C \le B$, and end with the exact canonical \texttt{effects} sequence.

\subsection{Launcher Framing, Allowlist, and Kernel Confinement Specification}
The confinement launcher spawns untrusted proposers over dedicated standard-input and standard-output pipes with error streams discarded, inherited descriptors closed, an empty environment, and root working directory. Proposer line framing enforces a \VTwoLauncherCapBytes-byte UTF-8 cap (draining oversize lines and returning a denial without unbounded buffer growth). Schema validation permits only two proposer verbs---\emph{submit} and \emph{status}---rejecting any proposer-supplied actor identifier or control-plane verb (\emph{approve}, \emph{delegate}, \emph{withdraw}, \emph{renew}, \emph{settle}, \emph{fence}, \emph{init}, \emph{inspect}, \emph{audit}), injects the bound session actor server-side, and strips raw permit tokens from responses.

Inside the unprivileged Linux confinement wrapper:
\begin{enumerate}
\item \textbf{Landlock ABI $\ge 4$:} Queries the kernel Landlock ABI version (failing closed if $<4$), constructs a $16$-byte ruleset handling all $15$ filesystem access bits (including file truncation) and both TCP bind and TCP connect bits, attaches read/execute path rules solely for system shared-library directories, null and random character devices, and the canonicalized proposer binary, sets the kernel no-new-privileges flag, and restricts the calling process (zero TCP rules attached, denying all TCP bind and connect operations).
\item \textbf{Seccomp-BPF \texttt{EPERM} filter:} Pins the native system-call architecture (\texttt{0xc000003e} on x86-64, \texttt{0xc00000b7} on ARM64) and terminates compatibility-ABI system calls ($\ge \texttt{0x40000000}$). Permits resource-limit queries only when both $32$-bit halves of the target process-identifier argument equal zero, returning \texttt{EPERM} on cross-process inspection. Returns \texttt{EPERM} across $56$ additional system calls spanning network sockets (socket creation, pair, connect, bind, listen, accept, and datagram/message send), process inspection and signaling (process trace, cross-process virtual-memory read/write, process file descriptors, process/thread signal delivery, and descriptor comparison), namespaces, mounts, and kernel interfaces (mount/unmount, namespace unshare/reassociate, eBPF, performance events, user-space page-fault handling, asynchronous I/O rings, file-handle open, reboot, and kernel image load), kernel keyrings, System~V shared memory, message queues, and semaphores, and POSIX message queues.
\item \textbf{Descriptor sweep and native probes:} Sweeps all file descriptors $\ge 3$ via kernel close-range before executing the proposer binary. Automated validation pairs unrestricted positive canaries against confined probes across all \VTwoProbes{} checks (\VTwoBaseProbes{} compiled binary probes plus a live inherited System~V private queue probe verifying that unrestricted queue writes succeed while confined writes fail with \texttt{EPERM}).
\end{enumerate}

\subsection{22-Action Finite-State Model and Single-Database SQLite Baseline}
To anchor our separate-process protocol against an exhaustive finite-state baseline, we retain both a 22-action finite-state model checker and a single-database transactional SQLite executor.

In the finite-state model, each state is the tuple $x = (z, L, U, z_0, z_1, l, v, p_0, p_1)$, tracking world spend $z$, accounting ledger $L$, 4-bit executed-identifier mask $U$, per-actor spend $(z_0, z_1)$, grant liveness $l \in \{0,1\}$, environment version $v \in \{0,1\}$, and per-actor pending slots $(p_0, p_1)$. The 22-action alphabet comprises $16$ preparations ($a \in \{0,1\}$, $\mathit{id} \in \{0,1\}$, $q \in \{1,2\}$, $\mathit{dest} \in \{\mathrm{true},\mathrm{false}\}$), $2$ commits, revocation, version-advance with revocation, process restart, and grant renewal. Cycle-closed breadth-first search checks all $22$ actions per reachable accepted state against $20$ positive tasks ($8$ single transactions plus $12$ ordered pairs of $1$-unit identifiers) and an independent pre-effect world oracle.
