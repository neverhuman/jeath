\section{Protocol Transitions, Finite-State Models, and Boundary Schemas}
\label{app:protocol}

This appendix records the exact storage schemas, RPC transition rules, Linux confinement filters, Verus \path{policy-core} verification inventory, and preserved V1 (\texttt{12b5579}) finite-state and single-database baselines referenced in Sections~\ref{sec:core} and~\ref{sec:eval}.

\subsection{V2 Broker and Sink Durable Schemas and Normalization}
Both \texttt{broker-v2} and \texttt{sink-v2} (\path{src/protocol_v2.rs}) require bundled SQLite $\ge 3.51.3$ (excluding historical WAL-reset corruption bugs \cite{sqlite-wal}), configure \texttt{PRAGMA journal\_mode=WAL}, \texttt{PRAGMA synchronous=FULL}, and a $10$\,s busy timeout, and execute every mutating RPC inside an explicit \texttt{BEGIN IMMEDIATE} write transaction \cite{sqlite-transaction}. Physically, each service database (\path{broker.sqlite} and \path{sink.sqlite}) initializes two SQLite tables:
\begin{itemize}
\item \texttt{state(singleton INTEGER PRIMARY KEY CHECK(singleton=1), body TEXT NOT NULL)}: stores the canonical JSON-serialized service state struct (\texttt{Broker} in \path{broker.sqlite}; \texttt{Sink} in \path{sink.sqlite}).
\item \texttt{effects(sequence INTEGER PRIMARY KEY, id TEXT UNIQUE NOT NULL, payload TEXT NOT NULL, charge INTEGER NOT NULL)}: used in \path{sink.sqlite} as an append-only committed effect log enforcing SQLite-level uniqueness on operation \texttt{id} and recording the canonical serialized \texttt{DispatchedPermit} alongside integer \texttt{charge}.
\end{itemize}

Table~\ref{tab:v2schema} maps the logical protocol collections onto these persisted structures. All wire structs carry \texttt{\#[serde(deny\_unknown\_fields)]}, so unrecognized JSON keys fail parsing prior to canonical re-serialization; JSON whitespace or key-order variations cannot mint distinct authorities.

\para{Normalized \texttt{DispatchedPermit} binding.}
For $n$ configured issuers ($1 \le n \le 64$, default $n = 2$), base operation requirements $\mathrm{req}_0(e, n)$ require issuer $0$ (operator) for \texttt{Transfer}, issuers $\{0,1\}$ (operator and steward) for \texttt{Edit}, and all $n$ issuers for \texttt{Release}. When a proposal is admitted via a sub-delegation leaf whose \texttt{required} vector strengthens $\mathrm{req}_0(e, n)$ (for example, adding steward requirement $j=1$ to a \texttt{Transfer}), \texttt{Broker::submit} embeds $\texttt{required} = \texttt{leaf.required}$ into \texttt{DispatchedPermit} (omitting the field only when equal to $\mathrm{req}_0(e,n)$, preserving canonical byte compatibility for non-delegated permits). At the sink, \texttt{DispatchedPermit::normalized} rejects any vector that weakens $\mathrm{req}_0(e,n)$ and supplies \texttt{effective\_required} to \texttt{accept}, \texttt{complete}, \texttt{fence}, and \texttt{audit}. Meanwhile, \texttt{Broker::submit} compares \texttt{same\_permit(\&r.permit.base\_permit(), \&permit)} on proposer retries so repeating a canonical \texttt{actor + proposal} returns its stored status and \texttt{DispatchedPermit} idempotently without allowing a stripped sink replay.

\subsection{V2 Broker and Sink RPC Transition Specification}
Every service line is framed by \texttt{read\_rpc\_frame} with cap $\texttt{MAX\_RPC\_BYTES} = \text{\VTwoServiceCapBytes}$ bytes (oversize lines drain to \texttt{\textbackslash n} and return \texttt{denied("rpc\_too\_large")} without process termination). Optional test hooks \texttt{delay\_before\_commit\_ms} ($\le 1000$\,ms), \texttt{crash = "before\_commit"} (exit code $86$ prior to \texttt{tx.commit()}), and \texttt{crash = "after\_commit"} (exit code $87$ immediately after \texttt{tx.commit()}) exercise real WAL lock contention and crash recovery.

\para{Broker transitions (\path{broker.sqlite}).}
\begin{itemize}
\item \texttt{init(budget, issuers?)}: Fails if \texttt{state} exists; otherwise initializes $B = \texttt{budget}$, $C = 0$, $\texttt{epochs} = 0^n$, $\texttt{live} = \mathrm{true}^n$, and empty \texttt{approvals}, \texttt{records}, and \texttt{delegations}.
\item \texttt{approve(permit, issuer $j$)}: Requires $\texttt{live}[j]$ and $\texttt{permit.proposal.epochs} = \texttt{epochs}$, no ID collision in \texttt{delegations}, and exact byte match (\texttt{same\_bytes}) if an approval for \texttt{proposal.id} already exists; sets $\texttt{grants}[j] \leftarrow \mathrm{true}$.
\item \texttt{delegate(id, parent?, permit?, budget, expires, scope, required?, grants?, epochs?)}: Verifies acyclicity of ancestor chain, live/current ancestor grants via \texttt{current\_grants}, absence of non-cancelled direct spend on any ancestor approval/delegation ID, and \texttt{attenuates} between parent and child capabilities before appending the \texttt{Delegation}.
\item \texttt{submit(proposal, session\_actor)}: If \texttt{proposal.id} exists in \texttt{records}, returns existing \texttt{(status, permit)} iff \texttt{base\_permit} matches \texttt{session\_actor + proposal}, else \texttt{denied("payload\_mismatch")}. Otherwise checks \texttt{scoped()}, verifies direct approval or full ancestor delegation chain via \texttt{current\_grants} and \texttt{admit\_multi}, reserves $C' = \texttt{reserve}(B, C, q)$ (and $C'_d = \texttt{reserve}(B_d, C_d, q)$ along any delegation chain), persists \texttt{Record\{permit: dispatched, status: Pending\}}, and returns \texttt{pending}.
\item \texttt{withdraw(issuer $j$)}: Sets $\texttt{epochs}[j] \leftarrow \texttt{epochs}[j] + 1$, $\texttt{live}[j] \leftarrow \mathrm{false}$, clears $\texttt{grants}[j]$ across all \texttt{approvals} and \texttt{delegations}, and reports $\texttt{outstanding} = \sum \{q_r : r.\texttt{status}=\texttt{Pending} \land \mathrm{eff\_req}(r)[j]\}$.
\item \texttt{renew(issuer $j$)}: Sets $\texttt{live}[j] \leftarrow \mathrm{true}$ without restoring cleared grant bits, altering \texttt{epochs}, or reducing $C$.
\item \texttt{settle(id, sink\_status)}: Control-plane endpoint (never exposed to proposers). Requires existing \texttt{Pending} record and $\texttt{sink\_status} \in \{\texttt{Committed}, \texttt{Cancelled}\}$; updates $C \leftarrow \texttt{release}(C, q, \texttt{sink\_status} == \texttt{Cancelled})$ (and ancestor delegation charges) and sets terminal status.
\item \texttt{status(id, session\_actor)} / \texttt{inspect} / \texttt{audit}: Read-only queries; \texttt{audit} runs \texttt{PRAGMA integrity\_check} and checks ID uniqueness, delegation bounds, and $\sum_{\texttt{Pending}} q + \sum_{\texttt{Committed}} q = C \le B$.
\end{itemize}

\para{Sink transitions (\path{sink.sqlite}) and concurrent linearization.}
\begin{itemize}
\item \texttt{accept(permit)}: Normalizes \texttt{Dispatched\allowbreak Permit}. If \texttt{proposal.id} is already recorded, returns stored status iff \texttt{same\_\allowbreak dispatched\_\allowbreak permit} holds, else \texttt{denied("payload\_\allowbreak mismatch")}. If new and \texttt{!unfenced(\allowbreak eff\_req, epochs, floors)}, persists a terminal \texttt{Cancelled} tombstone; otherwise persists \texttt{Pending}.
\item \texttt{complete(id)}: Requires recorded \texttt{id}. If \texttt{Pending}, evaluates \texttt{unfenced(\allowbreak eff\_req, epochs, floors)} and (for \texttt{Edit}) \texttt{revision\_\allowbreak matches(\allowbreak revision, expected\_\allowbreak revision)}. Failure transitions status to \texttt{Cancelled}; success updates \texttt{document}/\allowbreak\texttt{revision} if applicable, transitions status to \texttt{Committed}, and inserts the unique row into \texttt{effects} in the same \texttt{BEGIN IMMEDIATE} transaction. Terminal records return stored status idempotently.
\item \texttt{fence(issuer $j$, floor)}: Updates $\texttt{floors}[j] \leftarrow \texttt{advance\_floor}(\texttt{floors}[j], \texttt{floor})$ and transitions every \texttt{Pending} record failing \texttt{unfenced} to \texttt{Cancelled} before committing and returning acknowledgment.
\item \texttt{status(id)} / \texttt{inspect} / \texttt{audit}: \texttt{status} returns \texttt{unknown} when absent (never treated as cancellation); \texttt{audit} verifies \texttt{PRAGMA integrity\_check}, \texttt{unfenced} on all remaining \texttt{Pending} permits, and exact payload/charge bijection between \texttt{Committed} records and \texttt{effects}.
\end{itemize}
For concurrent separate-process runs, \path{scripts/concurrent_v3.py} checks real-time interval linearizability against the independent Python \texttt{Reference}: an invocation $e_j$ must precede $e_i$ whenever $\texttt{responded\_ns}(e_j) < \texttt{invoked\_ns}(e_i)$; pre-commit crashes (\texttt{exit 86}) commit \texttt{False}, post-commit crashes (\texttt{exit 87}) commit \texttt{True}, and unannotated dropped replies branch over $\{\texttt{False}, \texttt{True}\}$. Every linearized prefix must match recorded decision and public \texttt{status} responses, maintain $0 \le C \le B$, and end with the exact canonical \texttt{effects} list (excluding non-atomic \texttt{inspect}/\texttt{audit} snapshots, rejecting expiry-crossing intervals, and returning \texttt{inconclusive} beyond $\le \VTwoLinearizedMaxCalls$ calls or $10^5$ search nodes).

\subsection{Launcher Framing, Allowlist, and Kernel Confinement Specification}
\path{scripts/launch_v2.py} spawns untrusted proposers via \texttt{authority-lab confine-v2} with \texttt{stdin=PIPE}, \texttt{stdout=PIPE}, \texttt{stderr=DEVNULL}, \texttt{close\_fds=True}, \texttt{env=\{\}}, and \texttt{cwd="/"}. \texttt{read\_proposer\_line} enforces a \VTwoLauncherCapBytes-byte UTF-8 frame cap (draining oversize lines and returning \texttt{denied} without unbounded buffer growth; blocking line reads bound per-frame memory rather than wall-clock execution time). \texttt{validate\_message} permits only two exact proposer schemas---\texttt{\{"op": "submit", "proposal": ...\}} and \texttt{\{"op": "status", "id": ...\}}---rejecting any proposer-supplied \texttt{actor} key or control verb (\texttt{approve}, \texttt{delegate}, \texttt{withdraw}, \texttt{renew}, \texttt{settle}, \texttt{fence}, \texttt{init}, \texttt{inspect}, \texttt{audit}), injects \texttt{session\_actor} server-side, and strips \texttt{permit} tokens from responses.

Inside \texttt{confine-v2} (\path{src/isolation_v2.rs} and \path{src/bin/authority-lab.rs}):
\begin{enumerate}
\item \textbf{Landlock ABI $\ge 4$:} Queries \texttt{SYS\_landlock\_\allowbreak create\_\allowbreak ruleset} ABI version (failing closed if $<4$), constructs the $16$-byte \texttt{RulesetAttr} with \texttt{handled\_\allowbreak access\_fs} $= \texttt{0x7fff}$ (all $15$ filesystem access bits through \texttt{TRUNCATE}) and \texttt{handled\_\allowbreak access\_net} $= \texttt{3}$ (\texttt{BIND\_TCP | \allowbreak CONNECT\_TCP}), attaches read/execute \texttt{O\_PATH} rules solely for \path{/usr}, \path{/lib}, \path{/lib64}, \path{/bin}, \path{/etc/ld.so.cache}, \path{/dev/null} (read/write), \path{/dev/urandom}, and the canonicalized proposer executable, sets \texttt{PR\_SET\_\allowbreak NO\_NEW\_\allowbreak PRIVS}, and calls \texttt{SYS\_landlock\_\allowbreak restrict\_self} (zero TCP rules added, blocking all TCP bind/connect).
\item \textbf{Seccomp-BPF \texttt{EPERM} filter:} Pins \texttt{seccomp\_\allowbreak data.arch} (\texttt{0xc000003e} on \texttt{x86\_64}, \texttt{0xc00000b7} on \texttt{aarch64}) and kills x32/compat syscall numbers ($\ge \texttt{0x40000000}$). Allows \texttt{SYS\_prlimit64} only when \emph{both} 32-bit halves of the 64-bit PID argument (offsets $16$ and $20$) equal zero, returning \texttt{EPERM} on cross-process inspection. Returns \texttt{EPERM} across $56$ additional syscalls: sockets (\texttt{socket}, \texttt{socketpair}, \texttt{connect}, \texttt{bind}, \texttt{listen}, \texttt{accept}, \texttt{accept4}, \texttt{sendto}, \texttt{sendmsg}, \texttt{sendmmsg}), process inspection/signaling (\texttt{ptrace}, \texttt{process\_vm\_\allowbreak readv}, \texttt{process\_vm\_\allowbreak writev}, \texttt{pidfd\_getfd}, \texttt{pidfd\_open}, \texttt{pidfd\_send\_\allowbreak signal}, \texttt{kill}, \texttt{tkill}, \texttt{tgkill}, \texttt{rt\_sigqueue\allowbreak info}, \texttt{rt\_tgsigqueue\allowbreak info}, \texttt{kcmp}), namespaces/mounts/kernel (\texttt{mount}, \texttt{umount2}, \texttt{unshare}, \texttt{setns}, \texttt{bpf}, \texttt{perf\_event\_\allowbreak open}, \texttt{userfaultfd}, \texttt{io\_uring\_\allowbreak setup}, \texttt{io\_uring\_\allowbreak enter}, \texttt{io\_uring\_\allowbreak register}, \texttt{open\_by\_\allowbreak handle\_at}, \texttt{reboot}, \texttt{kexec\_load}), keyrings (\texttt{add\_key}, \texttt{request\_key}, \texttt{keyctl}), System~V IPC (\texttt{shmget}, \texttt{shmat}, \texttt{shmctl}, \texttt{shmdt}, \texttt{msgget}, \texttt{msgsnd}, \texttt{msgrcv}, \texttt{msgctl}, \texttt{semget}, \texttt{semop}, \texttt{semtimedop}, \texttt{semctl}), and POSIX message queues (\texttt{mq\_open}, \texttt{mq\_unlink}, \texttt{mq\_timed\allowbreak send}, \texttt{mq\_timed\allowbreak receive}, \texttt{mq\_notify}, \texttt{mq\_get\allowbreak setattr}).
\item \textbf{Descriptor sweep and native probes:} Invokes \texttt{SYS\_close\_range(3, u32::MAX, 0)} and \texttt{exec}s with minimal environment. \path{run_v2.py} pairs unrestricted positive canaries against confined probes across all \VTwoProbes{} checks (\VTwoBaseProbes{} Rust binary probes plus \path{existing_sysv_queue}, where the parent creates an \texttt{IPC\_PRIVATE | 0600} queue, verifies unrestricted \texttt{msgsnd}/\texttt{msgrcv} succeed, verifies confined \texttt{msgsnd} fails with \texttt{EPERM}, and removes the queue via \texttt{IPC\_RMID}).
\end{enumerate}

\subsection{Preserved V1 Finite-State Model and Atomic SQLite Baseline}
To preserve exact backward reproducibility with commit \texttt{12b5579} (\path{evidence/reference/}, verified by \path{scripts/validate.py} \texttt{-{}-source-ref 12b5579}), we retain both the V1 22-action finite-state model (\path{src/model.rs}) and the V1 single-database transactional executor (\path{src/runtime.rs}).

In the V1 finite-state model, each state is the tuple $x = (z, L, U, z_0, z_1, l, v, p_0, p_1)$, tracking world spend $z$, accounting ledger $L$, 4-bit executed-identifier mask $U$, per-actor spend $(z_0, z_1)$, grant liveness $l \in \{0,1\}$, environment version $v \in \{0,1\}$, and per-actor pending slots $(p_0, p_1)$. The 22-action alphabet comprises $16$ preparations $\texttt{Prepare}(a \in \{0,1\}, \mathit{id} \in \{0,1\}, q \in \{1,2\}, \mathit{dest} \in \{\mathrm{true},\mathrm{false}\})$, $2$ commits $\texttt{Commit}(a)$, \texttt{Revoke}, \texttt{Advance} (advancing $v: 0 \to 1$ and revoking $l$), \texttt{Restart}, and \texttt{Renew}. Cycle-closed breadth-first search checks all $22$ actions per reachable accepted state against $20$ positive tasks ($8$ single transactions plus $12$ ordered pairs of $1$-unit identifiers) and an independent pre-effect world \texttt{oracle}. Table~\ref{tab:results} reports the complete atomic enforcer (\CheckedStates{} states, \CheckedEdges{} checks, $0$ violations), unconstrained and reject-all baselines, nine targeted single-clause enforcer mutations (\texttt{per\_action}, \texttt{per\_actor}, \texttt{prepare\_only}, \texttt{no\_replay}, \texttt{no\_revocation}, \texttt{no\_version}, \texttt{no\_destination}, \texttt{reset\_restart}, \texttt{reset\_renewal}), and the specification-omission control (\OmittedStates{} states, \OmittedEdges{} checks, spending $8$ units against budget $2$).
