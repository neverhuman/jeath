\section{Verified Policy Core, Revocation Semantics, and Process Confinement}
\label{sec:core}

Section~\ref{sec:theory} showed that bounding operational reach requires an external stateful gate whose admission rule contracts monotonically with state uncertainty $\mathcal{B}_t$ (Condition~C1) and whose revocation transition halts in-flight capability exercise rather than merely stopping token generation \cite{saltzer,schneider,controlroom} (Condition~C6). Whereas our preserved V1 baseline (\texttt{12b5579}; Appendix~\ref{app:protocol}) colocates policy state, receipts, and toy effects inside one SQLite database, practical tool execution spans separate processes without cross-service atomic transactions \cite{ftbudget,limbo}. V2 therefore splits authority across two separate OS processes owning independent SQLite (\texttt{WAL}, \texttt{synchronous=FULL}) stores \cite{sqlite-transaction,sqlite-wal}: a \emph{Broker} (\path{broker.sqlite}) governing approvals, delegations, epochs, and reservations, and a \emph{Cooperative Idempotent Sink} (\path{sink.sqlite}) governing monotone epoch fences, deduplication, versioned resources, and committed effects.

\subsection{Pre-Dispatch Reservation and Uncertainty Quarantine}
Let $B$ denote cumulative budget, $C_{\mathrm{comm}}$ the charge of committed sink effects, and $I_t$ the unresolved issued permits with positive maximum charges $\{q_i\}_{i \in I_t}$. Because any subset of $I_t$ may already have committed or still arrive, true spend lies in $\mathcal{B}_t = [C_{\mathrm{comm}},\, C_{\mathrm{comm}} + \sum_{i \in I_t} q_i]$, and broker charged authority $C = C_{\mathrm{comm}} + \sum_{i \in I_t} q_i$ tracks the exact upper endpoint of $\mathcal{B}_t$.

Before any permit crosses the dispatch pipe, the broker executes an immediate write transaction checking overflow-safe capacity ($q > 0$, $q \le B$, $C \le B - q$), persists the pending record, and sets $C' = C + q$. Persisting that record linearizes admission; retrying an identical request after a post-commit broker crash returns the stored pending permit without charging twice. Crucially, \texttt{release} takes no timeout parameter: ambiguous outcomes---\texttt{pending}, \texttt{unknown} at a sink lookup, EOF, or \texttt{lost\_reply} after a post-commit sink crash---never refund $C$. Only an authoritative terminal sink \texttt{Cancelled} receipt releases $q$, while \texttt{Committed} settles $q$ permanently into consumed spend, trading temporary budget availability under faults for strict cumulative conservation.

\subsection{Admission vs.\ Sink-Fenced Revocation and Sub-Delegation}
Revocation operates independently per required issuer $j \in \{0,\dots,n-1\}$ and separates issuance from sink execution:
\begin{enumerate}
\item \textbf{Admission revocation.} At broker instant $r$, \texttt{withdraw}$(j)$ atomically increments $\texttt{epochs}[j]$, sets $\texttt{live}[j] \leftarrow \mathrm{false}$, and clears issuer-$j$ grant bits across approvals and delegations (never restored by subsequent \texttt{renew}$(j)$). New old-epoch issuance halts, leaving post-withdrawal effect exposure from in-flight permits $P_r$ bounded under sink deduplication ($0 \le e_i \le q_i$) by retained reservations:
\begin{equation}
\sum_{i \in P_r} e_i \;\le\; \sum_{i \in P_r} q_i.
\label{eq:admission-exposure}
\end{equation}
\item \textbf{Sink-fenced revocation.} Next, \texttt{fence}$(j, \mathrm{floor})$ executes a serialized \texttt{BEGIN IMMEDIATE} transaction on \path{sink.sqlite} advancing $\texttt{epoch\_floor}[j] \leftarrow \max(\texttt{epoch\_floor}[j], \mathrm{floor})$, marking pending permits requiring $j$ below the floor \texttt{Cancelled}, and recording durable \texttt{Cancelled} tombstones on late first arrivals (permitting broker release). Because sink \texttt{complete} checks \texttt{unfenced} under the same write lock, any competing completion either commits prior to the fence or is rejected afterward; returning acknowledgment at $a$ after commit guarantees strictly zero post-acknowledgment effects under old authority:
\begin{equation}
\sum_{i \in P_r} e_i^{(>a)} \;=\; 0.
\label{eq:fenced-zero}
\end{equation}
\end{enumerate}

For multi-issuer quorums and sub-delegation chains \cite{dennis}, \texttt{attenuates} ensures a child capability never expands parent budget, expiry, or operation scope and never drops required issuers ($\texttt{parent\_req}[j] \Rightarrow \texttt{child\_req}[j]$), while allowing strengthened requirements. Because a base \texttt{Transfer} requires only the operator ($\texttt{[true, false]}$), reconstructing requirements from effect kind alone at the sink would drop an added steward requirement ($\texttt{[true, true]}$) and bypass a steward fence. \texttt{DispatchedPermit} therefore immutably binds any strengthened \texttt{required} vector across broker issuance and sink \texttt{permits}/\texttt{effects}/\texttt{fence}/\texttt{complete} checks, while \texttt{Broker::submit} preserves canonical \texttt{actor + proposal} proposer retry identity.

\subsection{Kernel Proposer Confinement and Availability Scope}
\path{launch_v2.py} and \texttt{confine-v2} isolate untrusted Linux proposers without user namespaces \cite{landlock,seccomp}. The launcher binds each stdio pipe to a fixed \texttt{session\_actor}, allows only \texttt{submit} and \texttt{status}, sets \texttt{stderr=\allowbreak subprocess.DEVNULL} (preventing Landlock bypass via an inherited writable \texttt{fd 2}), clears the environment, and caps proposer frames at \VTwoLauncherCapBytes{} bytes (\VTwoServiceCapBytes{} bytes on service pipes). Before \texttt{exec}, \texttt{confine-v2} sets \texttt{PR\_SET\_\allowbreak NO\_NEW\_PRIVS}, installs a 16-byte Landlock ABI~$\ge 4$ filesystem and TCP ruleset (\texttt{handled\_access\_net = 3}), installs an architecture-checked seccomp-BPF \texttt{EPERM} filter blocking sockets, \texttt{ptrace}, \texttt{process\_vm\_*}, \texttt{pidfd\_*}, signals, \texttt{io\_uring\_*}, \texttt{bpf}, keyrings, nonzero 64-bit \texttt{SYS\_prlimit64}, and full System~V (\texttt{msgsnd}/\texttt{msgrcv}/\texttt{msgctl}/\texttt{sem*}/\texttt{shm*}) plus POSIX \texttt{mq\_*} IPC syscalls, and calls \texttt{close\_range(3, ..)}. Frame caps bound per-line memory allocation on blocking reads rather than guaranteeing wall-clock resource-exhaustion immunity; macOS CI runs portable functional checks without Linux confinement.
