\subsection{Reconstructing the finite model}
The supplied manuscripts describe a two-actor model but did not include their claimed Python artifacts. We therefore implement the stated transitions afresh in Rust, rather than certify the missing implementation or retain its execution claims. Each actor has two identifiers and one pending request; preparations choose amount one or two, approved or unapproved destination, and the current version. An external controller can revoke, advance version once, renew, or restart. The 22-action alphabet includes repeated requests and no-ops. Renewal preserves pending versions; correct restart and renewal preserve consumption, identifiers, and accounting.

The authorization function reads an accounting ledger. A separate event oracle reads actual consumption, identifier history, live-grant state, preparation version, and destination. Breadth-first search explores every reachable state accepted by the declared specification, records violating edges, and does not expand them. Every violating execution has such a first-violation edge. A visited-state map closes cycles without an arbitrary horizon. Parent links provide shortest witnesses. The implementation and oracle share one codebase and authoring process; separation of functions is not independent audit.

The useful-task suite covers eight single transactions and twelve ordered pairs of distinct one-unit identifiers. All 20 must remain executable for a useful passing result. A reject-all baseline exposes vacuity. No external enforcement is an unrestricted executable baseline, not a prompted-LLM experiment.

\subsection{Counterexamples and specification omission}
\label{sec:omission}
The shortest preparation-budget witness has four actions: prepare actor 0 for one unit, prepare actor 1 for two units, commit actor 0, commit actor 1. Both preparations fit the initially unused allowance, but their effects total three. A current atomic budget check rejects the second commit. Ledger-reset mutations need five actions: spend, reset accounting on restart or renewal, then spend against the erased ledger while real consumption persists. Replay, revoked-grant, stale-version, and destination mutations yield separate short traces recorded verbatim in \path{evidence/reference/model.json}.

For the specification control we retain the per-action enforcer but omit only the aggregate-budget predicate from declared acceptance. It accepts \OmittedStates{} states and \OmittedEdges{} edges with no declared violation and all positive tasks passing. Actual accepted consumption reaches eight, against the intended allowance of two. The unchanged reference oracle records overspend. This is a specification mutation, distinct from an implementation mutation; neither positive tasks nor an exhaustive checker identifies an omitted protected interest automatically.

\subsection{A real transactional prototype}
\label{sec:runtime}
The Rust executor uses bundled SQLite with write-ahead logging and \texttt{synchronous=FULL}. Each execution begins a write transaction with \texttt{BEGIN IMMEDIATE}, checks current policy and exact serialized request approvals, applies the effect, charges the shared ledger, and records a unique receipt in the same transaction. SQLite serializes write transactions \cite{sqlite-transaction}; crash recovery and durability additionally rely on the filesystem, storage, and SQLite assumptions \cite{sqlite-wal}.

Three protected effects are implemented: crediting a synthetic account, copying synthetic text into an approved mailbox table, and changing a versioned toy source document stored in the database. Releases and edits require both operator and steward grants; the executor checks document, destination, purpose, and revision where applicable. The toy source edit is not a filesystem or Git write. Required approvals bind the complete typed request, including actor, identifier, amount, epoch, expiry, and operation. A request identifier is immutable. A retry with identical contents returns its existing non-content receipt and does not repeat the effect; a changed payload is rejected. A previous release receipt does not re-return the released text.

Revocation increments an epoch. Renewal restores the live flag without resetting consumption, receipts, expiry, or old preparation epochs. Current-state checks and the effect share a serialization point. Expiry is checked before commit but is not a real-time deadline guarantee: scheduling and durable-write latency can delay commit. The service does not claim rollback of effects outside its database.

Eight scenario groups test useful effects; missing and withdrawn steward grants; tampering, scope, expiry and numeric boundaries; stale document revisions; revoke--renew--restart--retry sequences; process death immediately before and after commit; and four writers competing with 500 passive checkpoints. The process-death fixtures kill an actual worker after a flushed phase marker. Before-commit death leaves no effect; after-commit death leaves one effect, and retry retrieves the original receipt. These tests do not inject power loss, filesystem corruption, or distributed partitions. Source review identified the historical WAL-reset corruption bug, so the executor requires SQLite 3.51.3 or newer; the initially cached older bundle was replaced before the retained measurements \cite{sqlite-wal}. A bounded stress run does not prove absence of rare storage races.

Eight separate processes also compete to spend two units each from one shared two-unit budget: one commits and seven receive budget denials. Read-only audit snapshots compare receipts and the ledger with actual account balances, mailbox entries, and document revisions. Exported database observations are retained in \path{observed-effects.json}. Timing runs provision grants before measuring equal workloads with one or four processes; they report all operation latencies, including lock waits, with no learned-model latency on the commit path.

\subsection{The boundary of the result}
An offline JSONL adapter additionally scores six scripted campaigns through the same executor. Four unauthorized proposals yield zero unauthorized effects; five useful controls complete, while an abstain-only control fails usefulness. These are instrumentation and baseline checks, explicitly labeled scripted. External model outputs can use the same interface, but objective and persona metadata do not establish a training intervention. The adapter does not score semantic truthfulness or human susceptibility.

The proposer-facing API does not expose approval or renewal, but this prototype is a library and CLI, not an authenticated hosted service. Filesystem ownership, authenticated actor identity, role separation, and prevention of direct database writes remain assumptions. Giving the proposer the administrator CLI or the database file defeats the boundary. The finite abstraction and implementation differ in identifiers, epochs, scope, and crash mechanics; no formal refinement proof connects them. Their tests are complementary evidence, not interchangeable certificates. External payments, shell execution, arbitrary files, networking, physical effects, and persuasive human-mediated action remain outside the implemented effect model.
