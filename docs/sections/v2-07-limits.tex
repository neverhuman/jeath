\section{Limits, jurisdiction, and release conditions}
\label{sec:v2limits}
The result concerns synthetic local services, cooperative idempotent sinks, and
a declared proposer interface. It excludes distributed-ledger availability,
arbitrary external exactly-once execution, frontier-model generalization,
caretaker training, and human-participant evidence. The two named Qwen3
checkpoints are evaluation targets, not completed experiments. Their absence
prevents a claim about preserving usefulness under real evaluated model attacks.

\subsection{Trust does not disappear at a verified predicate}
The trusted base includes a typed parser, payload normalization, issuer-to-effect
mapping, launcher-created identity, storage serialization, durable recovery,
tool contracts, and the operating system. Verus, its solver, and the Rust
compilation path are also trusted. The proof neither establishes kernel
isolation nor verifies every caller of the core. Conversely, the Linux probes
do not prove the permission specification. Each evidence item has a narrower
object, identified in the release manifest.

The JSON state stored by the service is intentionally simple and suitable for
small CPU fixtures. It is not a production authorization database schema or a
claim of efficient scaling to large actor populations. The proof's arbitrary
finite population quantification is a logical property of the interface and
conservation algebra. Runtime limits, parser memory, process count, and storage
contention still bound the implementation. Resource-exhaustion resistance and
multi-tenant confidentiality require additional work.

The sandbox uses a declared filesystem allowlist and syscall restrictions. The
launcher fails closed on unsupported kernels and does not substitute an
unrestricted run while retaining a confined label. The macOS job checks portable
functionality but makes no Linux isolation claim. Passing one kernel's native
probes is evidence about those attempted paths, not an exhaustive proof about
all kernels or future syscall additions. Kernel and filter changes require a
fresh run and source identifier.

The independent history checker also has a defined scope. Its fault histories
are sequential at the RPC level. Concurrent races check independent effects and
conservation, and the delayed-fence test checks an observed lock ordering. Full
linearizability checking over arbitrary overlapping service histories remains
unimplemented. The current evidence cannot be described as exhaustive actor
interleaving verification for the whole runtime.

\subsection{Encoded authority and legitimate jurisdiction}
A technical grant identifies what this system will permit. It does not establish
that the grant owner may legitimately authorize every effect on affected people,
data, or institutions. Requiring both operator and steward demonstrates a
conjunction mechanism; it does not establish that those two roles exhaust all
relevant rights. Correctly enforcing an incomplete list can faithfully carry out
an illegitimate action. The approved-but-incorrect document is a small technical
analogue of this specification problem, not evidence about political consent.

Careful governance therefore remains outside the authorization theorem.
Jurisdiction, contestability, privacy, and obligations to affected communities
must be established by accountable processes. The concise claim here is that
withdrawal by a required issuer has an explicit technical consequence under the
specified interface. Neither model capability nor a claim of care creates a new
issuer, expands the budget, or justifies removing a required grant. The longer
caregiver and human-delegation hypotheses remain in the appendices as untested
research proposals.

\subsection{Acceptance and reproducibility}
The release gate checks source preservation, formatting and lint, Rust and
Python tests, fresh v1 evidence, a v2 CPU smoke run, core verification, independent
trace and effect checks, semantic positive and negative controls, isolation
probes on Linux, fault regressions, generated tables, and the paper build. The
publication profile increases repeated host measurements but does not allocate
a GPU. CI retains Linux protocol/isolation checks and macOS functional checks.
Exact-head CI results identify the tested revision rather than an older green
commit on the same branch.

Model inference is separately governed by the fixed budget and frozen-analysis
manifest. A future run must preserve failures and inconclusive bounds; it must
not increase the GPU allowance after discovering an unfavorable outcome. A
feasibility failure is reported as such. Until GPU execution of the managed inference path and
the five-controller model campaigns are complete, the corresponding acceptance
item remains open. A source release can be useful and reviewable while that
scientific claim remains unsupported.

The practical result is an explicit answer to the stopping question. After
admission withdrawal, retained reservations account for the authority still in
flight. After a cooperative sink's durable fence acknowledgment, old-authority
effects are excluded by the declared ordering and epoch contract. Achieving that
stronger boundary can consume time and strand budget. Those costs, the trusted
premises, and the unrun model comparison are part of the result.
