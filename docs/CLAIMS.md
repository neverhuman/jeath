# Claim-to-Evidence Map (Unified V1 / V2 / V3 Release)

Claims in this repository are partitioned across **five explicit evidence tiers** so that mechanized core theorems, finite-state enumerations, local SQLite/Linux systems tests, synthetic statistical simulations, and unexecuted model or human protocols are never conflated:

- **Tier 1 — Mechanized `policy-core` Verus proofs:** verified obligations, `exec` functions and theorems as counted in `evidence/v2/reference/proof.json` (and `docs/generated/v2-numbers.tex`), with `10` soundness mutations rejected (`scripts/verify_core.py`; rerun by the Linux local gate and CI). **Boundary:** proves properties of the verified kernel functions and canonical wire injectivity, **not** the unverified Rust decision logic around them in `src/protocol_v2.rs`, outer JSON framing, SQLite WAL, or OS-kernel refinement (see the paper's Section on the authority kernel for the release-build status).
- **Tier 2 — Exhaustive finite-state checks & exact mathematics:** V1 finite reachable-state closure (`10,180` states / `223,960` checks; `41,732`-state omitted-budget control), V2 abstract protocol omission search (`55/55` single and pairwise witnesses across `296` traces over `10` mechanisms), exact 3-step concurrent snapshot enumeration (`1,030,301` triples at $B=100$), brute-force weighted-cut cross-checks (`2,048` small DAGs, `0` discrepancies), exact Fisher hypergeometric audit PMFs, and analytical proofs (`docs/sections/ua-mathematical-proofs.tex`).
- **Tier 3 — Separate-process local SQLite, simulated partition schedules, Linux OS & CPU LLM controls:** Separate `broker-v2` (`broker.sqlite`) and `sink-v2` (`sink.sqlite`) processes under WAL `synchronous=FULL` (SQLite `3.53.2`; the V5 three-shard cluster test uses `synchronous=NORMAL`), `31` sequential RPC fault/`SIGKILL`/slowloris-deadline histories, bounded in-memory schedule exploration (`tests/protocol_v2_interleavings.rs`), full-scale diamond-POR recorded-RPC interval linearization (`18/18` `1,2,4,8,16,32`-actor runs in `scripts/concurrent_v3.py`, `0` overspends), unaudited from-scratch Ed25519/HMAC-SHA256 Macaroons (`0/10,000` false accepts) + a single-process logical-time partition simulation over `AF_UNIX` socket pairs (not Jepsen; schedules with at least one post-ack leak: `0/1,000` cooperative vs `791` broker-only and `276` uncooperative), `11/11` Linux Landlock ABI v4 + seccomp + IPC confinement probes, operational AgentDojo `v1.2.2` + Linux IPC cutsets (`real_tool_cutsets.json`), `480` executed 5-step AgentDojo trajectories (`trajectory_monitors.json`), and `320` frozen CPU `Qwen3-4B`/`8B` holdout campaigns (`0 GPU-s`) plus live AgentDojo runs. **Boundary:** cooperative local SQLite/socket effects only—not OS sandbox verification, uncooperative external APIs, or frontier-LLM rates; pilot $N=32 < 113$ leaves formal Bonferroni claims inconclusive.
- **Tier 4 — Standalone deterministic pure-Rust `SplitMix64` simulation & neural RL suite:** `19` deterministic reference JSON artifacts (`evidence/v3/reference/*.json`, seed `20261110`, zero third-party Rust crates; `src/v3_*.rs`, `src/v4_*.rs`, `scripts/run_v3.py`, `scripts/validate_v3.py --source`), including `412`-parameter 2-layer neural policy-gradient RL (`neural_post_training.json`, `48` seeds). **Boundary:** measures mathematical and controlled neural MDP consequences of explicitly stated assumptions—not `scikit-learn` bit-replication, frontier-LLM RLHF, or ethnographic proof.
- **Tier 5 — Full-power model & human protocols and institutional governance:** Full-scale $N \ge 113$ paired 5-controller checkpoint power (`16` Bonferroni one-sided component claims at $\alpha = 0.05/16$ for `5` pp usefulness noninferiority), frontier transfer, predeclared $3\times 3\times 2$ LLM caretaker/human scope-conferral study (**unrun on GPUs or human participants; `0 GPU-s`**), and real-world stakeholder jurisdiction/legitimacy obligations.

The current broker and sink require the verified executable kernel to agree with each guarded transition and its projected post-state, in release builds as well as debug builds. Kernel disagreement or an unrepresentable state denies the operation and leaves its transaction unchanged. [Release guard scope and tests](RELEASE_KERNEL.md) distinguish this tested wrapper from formal refinement and from the earlier binaries used in model experiments.
